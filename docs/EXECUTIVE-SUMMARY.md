# Melspec 优化工作总结

## 汇报摘要

本工作从 exp001 的 CPU 算法优化出发，比较单节点 GPU、CPU+GPU 异构和
多节点实现。正式数据表明，GPU 计算本身很快，但完整 CLI 的搬运、同步和
输出开销更大。单节点 exp008 和三节点 exp009 分别将四用例合计降至
`2.733 s` 和 `2.186 s`，其中 exp009 相对 exp001 的 64 线程结果加速
`1.728x`。

## 结论

本工作围绕 4 个官方 melspec 用例完成了 CPU、GPU 和异构实现探索。所有正式
结果均通过 `4/4 PASS`。在已验证方案中，三节点 CPU 流水化实验 exp009 最快，
四用例合计 `2.186 s`，相比 exp001 的 64 线程 spread 结果 `3.777 s` 加速
`1.728x`。

## 关键发现

1. **exp001 的算法基础有效。** 打包半长度实数 FFT、稀疏 Mel、分块和
   OpenMP 将计算成本大幅降低。64 线程比 16 线程合计从 7.572 s 降至 3.777 s。
2. **GPU 算术并没有成为端到端瓶颈。** exp006 的 GPU 计算阶段约为
   0.16–0.23 s，但 H2D、D2H、cuFFT plan、stream 同步和文件输出吃掉了收益。
3. **CPU+GPU 异构没有超过纯 GPU。** exp003 调参中纯 GPU 为 5.102 s，
   CPU 分担 2% 后为 5.179 s。CPU/GPU 资源竞争和较慢一侧的尾部延迟抵消了
   分担收益。
4. **单节点优化重点在数据路径。** exp007 显示 default 中读取/归一化约
   0.20 s，计算约 0.50 s，转换/写入约 0.24 s。exp008 通过并行归一化、
   单 OpenMP 区域和直接 float32 输出把合计降至 2.733 s，峰值内存从约
   779 MB 降至 394 MB。
5. **三节点的主要收益来自本地读取和流水化。** 三节点 exp004 已降至
   2.533 s。exp009 再采用 exp008 的直接 float32 路径，把合计降至 2.186 s。
6. **当前剩余瓶颈是分布式写入。** exp009 的 default profile 中，每 rank
   计算约 0.13 s，分布式写入约 0.28 s。继续优化应先处理输出流水，而不是
   再增加 CPU/GPU 计算资源。

## 边界

- exp001 的 64 线程数值来自 job 275 的三次运行最小值，原 16 线程正式
  验证仍保留在报告第 4.4 节。
- job 411 的有效计时完成后，`perf stat` 因
  `perf_event_paranoid=4` 无权限退出。该失败不影响此前的计时。
- 当前结论仅适用于本仓库的四个官方用例和完整 CLI 数据路径，不应外推为
  CPU 在所有 melspec 工作负载上都快于 GPU。
